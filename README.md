# 🔔 Notification Service

Микросервис асинхронной обработки и ручной отправки уведомлений, построенный на базе **Spring Boot 3.2.2**, распределенной архитектуры **Spring Cloud (2023.0.0)** и **Java 21**. 

Сервис мгновенно реагирует на системные события экосистемы Apache Kafka, а также предоставляет внешний REST-интерфейс для ручной отправки Email-сообщений через протокол SMTP.

---

## 🛠️ Назначение и ключевой функционал

Сервис централизованно решает задачи оповещения клиентов в режиме реального времени:
* **Асинхронный стриминг (Kafka Consumer):** Слушает очереди сообщений и автоматически обрабатывает события (например, генерация `UserEvent` при создании или удалении аккаунта в `user-service`).
* **Интеграция с Почтой (SMTP):** Использование `spring-boot-starter-mail` и компонента `JavaMailSender` для отправки текстовых писем `SimpleMailMessage` на электронные адреса пользователей.
* **Ручное управление (REST API):** Предоставляет HTTP-эндпоинты для прямой отправки писем в обход брокера сообщений.
* **Отказоустойчивость (Circuit Breaker):** Внедрен инструмент **Resilience4j**. Он изолирует сбои внешних почтовых серверов, предотвращая каскадные падения системы и обеспечивая выполнение резервных сценариев.
* **Шаблонизация писем:** Использует встроенные HTML-шаблоны из папки `templates` и статические ресурсы из `static` для автоматической сборки писем.

---

## 🛡️ Реализация отказоустойчивости (Circuit Breaker)

Слой бизнес-логики отправки сообщений (`EmailService`) защищен с помощью аннотации `@CircuitBreaker(name = "emailService")`. 

При возникновении сетевых ошибок или недоступности SMTP-сервера, Resilience4j временно блокирует прямые вызовы к почтовой службе и автоматически перенаправляет трафик на резервный метод-заглушку (**Fallback**):

* **Основной метод:** `sendNotification(...)` — осуществляет отправку и логирует успешный результат.
* **Запасной сценарий:** `fallbackSendNotification(..., Throwable t)` — перехватывает исключение, предотвращает аварийное завершение потока, логирует причину сбоя и сохраняет данные недоставленного уведомления в системный журнал.

## 📨 Шаблоны и темы уведомлений

Все системные уведомления имеют строго предопределенные контракты тем и содержимого (описаны в `ApiConstants`):

* **Адрес отправителя по умолчанию:** `no-reply@yourwebsite.com`
* **Событие `CREATE` (Регистрация):**
  * *Тема:* `Добро пожаловать!`
  * *Текст:* `Здравствуйте! Ваш аккаунт на сайте успешно создан.`
* **Событие `DELETE` (Удаление):**
  * *Тема:* `Аккаунт удален`
  * *Текст:* `Здравствуйте! Ваш аккаунт был удалён.`

## 🛰️ Спецификация REST API (Endpoints)

Внешние клиенты (или администраторы системы через `api-gateway`) могут отправлять произвольные уведомления напрямую. Все HTTP-запросы проходят через префикс пути `/notifications`.

### Список доступных ресурсов:

| Метод | URL-путь | Описание контракта | Параметры запроса (Query Params) |
| :--- | :--- | :--- | :--- |
| **POST** | `/notifications/send` | Ручная отправка произвольного Email | `email` (String)<br>`subject` (String)<br>`message` (String) |

### Пример cURL-запроса на ручную отправку:
```bash
curl -X POST "http://localhost:8080/notifications/send" \
     -d "email=user@example.com" \
     -d "subject=Важное оповещение" \
     -d "message=Текст вашего уведомления"
```
*При отправке через общий шлюз запрос адресуется на порт `8080`, после чего `api-gateway` автоматически перенаправляет его на инстанс сервиса уведомлений.*

## 📊 Интеграция с брокером Apache Kafka

Помимо HTTP-интерфейса, сервис асинхронно обрабатывает поступающие из брокера бизнес-события с помощью компонента `UserEventConsumer`, который делегирует логику маршрутизации в `NotificationService`.

* **Слушатель топика:** Аннотированный метод `@KafkaListener` динамически считывает имя топика из централизованного свойства `${spring.kafka.topic.name}`.
* **Идентификатор группы потребителей:** `notification-group`

### Пример структуры JSON-сообщения в топике:
```json
{
  "email": "ivan@example.com",
  "actionType": "CREATE"
}
```

## 💻 Технологический стек

* **Runtime:** Java 21 (LTS).
* **Core Framework:** Spring Boot 3.2.2 & Spring Web (Tomcat).
* **Cloud Infrastructure:** Spring Cloud Config Client & Netflix Eureka Client.
* **Messaging:** `spring-kafka` для обработки потока событий.
* **Fault Tolerance:** `io.github.resilience4j:resilience4j-spring-boot2`.
* **Тестирование:** JUnit 5 + `spring-kafka-test` для интеграционного тестирования очередей.

## ⚙️ Конфигурация окружения (Cloud Config)

Микросервис подключен к серверу конфигураций. Локальный файл `application.yml` инициализирует только метаданные связи:

```yaml
spring:
  application:
    name: notification-service
  config:
    import: "optional:configserver:http://localhost:8888/"
```

*Все рабочие параметры (настройки хоста SMTP-сервера, порты, топики Kafka, параметры `group-id` для консьюмеров и настройки тайм-аутов Resilience4j) динамически подтягиваются из файла `notification-service.yml` на удаленном Config Server.*

## 📂 Архитектурная структура модулей

```text
notification-service/
├── gradle/wrapper/          # Настройки сборщика Gradle Wrapper
└── src/
    ├── test/                # Интеграционные тесты логики консьюмеров и заглушек Kafka
    └── main/
        ├── resources/       # Конфигурационные файлы приложения
        │   ├── static/      # Статические ресурсы для писем (логотипы, стили CSS)
        │   └── templates/   # Шаблоны писем
        └── java/io/gsc/     
            ├── NotificationServiceApplication.java # Главный класс запуска микросервиса
            ├── consumer/    # Компонент UserEventConsumer для чтения из Kafka
            ├── controller/  # REST-контроллер NotificationController для ручной отправки писем
            ├── service/     # Сервисный слой: EmailService (Circuit Breaker) и NotificationService
            └── model/       
                ├── event/   # Схемы принимаемых из брокера объектов (UserEvent)
                └── constants/ # Класс ApiConstants с темами и текстами писем
```

## 🚀 Команды для сборки и локального запуска

Проект компилируется и собирается с помощью Gradle. Для локального запуска необходима установленная **Java 21**.

* **Сборка проекта в переносимый JAR-файл (с пропуском тестов):**
  ```bash
  ./gradlew clean build -x test
  ```
* **Локальный запуск артефакта через терминал:**
  ```bash
  java -jar build/libs/notification-service-0.0.1-SNAPSHOT.jar
  ```
* **Запуск тестов:**
  ```bash
  ./gradlew test
  ```
